# 外部レビューの指摘の扱い

CodeRabbit などの bot が出すレビュー指摘は **事実ではなく仮説** として扱う。指摘の内容を検証せずに適用しない。

## typo 修正は適用前に既存の綴りを grep する

識別子・テーブル名・カラム名・文字列リテラル・環境変数名に対する typo 修正の指摘は、適用前にリポジトリ全体で既存の綴りを検索する。

- ヒットが複数箇所ある綴りは、意図的な命名か既に稼働している名前である可能性が高い
- DB のテーブル名・カラム名、外部 API のフィールド名、永続化されたデータのキーは、綴りが誤っていても単独では変更できない。変更するとデータやスキーマとの不整合が起きる
- 綴りを変える場合は、影響範囲（マイグレーション、既存データ、他リポジトリからの参照）を示してユーザーに確認する

過去に、検証せずに本番テーブル名の綴りを修正して revert が必要になった。綴りの誤りは修正すべき対象に見えるが、稼働中の名前は誤っていても正しい状態として扱う必要がある。

## 指摘に反論する場合

技術的に誤っている指摘、YAGNI に反する指摘には反論する。反論には具体的な根拠を添える。指摘を受けたという理由だけで変更しない。

受け止め方の詳細は `superpowers:receiving-code-review` スキルに従う。
