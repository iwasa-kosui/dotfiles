# リポジトリとアカウントのスコープ判断

「この変更は別のリポジトリで行うべき」と結論する前に、現在のリポジトリで扱えないことを **根拠を示して** 確認する。根拠なしにスコープ外と判断しない。

## Terraform や IaC を含むリポジトリの場合

対象の AWS アカウント ID、provider alias、assume role の対象を現在のリポジトリで検索する。

```
grep -rnE "<アカウントID>|<provider alias 名>" --include='*.tf' .
```

- ヒットがあれば、そのアカウントを現在のリポジトリから扱える。「アクセス権がない」と主張しない
- ヒットがなくても即断しない。`provider` ブロック、`assume_role` の設定、backend の設定を確認する。アカウント ID が変数やリモート state 経由で渡っている場合、ID の直接検索ではヒットしない
- 判断を報告するときは、確認したファイルと検索結果を根拠として示す

複数アカウントへのクロスアカウントアクセスを持つリポジトリは珍しくない。アクセス範囲を推測で狭めない。

## Terraform を含まないリポジトリの場合

同じ原則を適用する。別リポジトリに属すると判断する前に、現在のリポジトリの設定・依存関係・CI 定義・デプロイ先を確認し、扱えない根拠を示す。
