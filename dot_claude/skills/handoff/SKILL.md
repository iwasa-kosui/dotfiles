# Handoff

現在のセッションで得た結論を引き継ぎドキュメントに書き出す。新しいセッションがこのドキュメントだけを読んで作業を再開できる状態にすることが目的。

## いつ使うか

- `context-guard` hook がコンテキスト量を警告し、作業を区切る段階に来たとき
- 「handoff を書いて」「引き継ぎを書いて」「セッションを区切って」のような明示的な依頼
- 長い調査が一段落し、次の作業単位に移る前
- 作業を中断して後日再開する見込みがあるとき

## 設計思想

1. **会話の要約ではなく結論を残す**: 自動圧縮は履歴を薄めて残すが、handoff は履歴を捨てて結論だけを残す。「何を試して何が分かったか」の経過は、結論に効いていないなら書かない
2. **再調査させない**: 次のセッションが同じファイルを読み直し、同じコマンドを叩き直すのを防ぐことが最大の価値。検証済みの事実は根拠付きで書く
3. **蒸し返させない**: 却下した案とその理由を残す。書かないと次のセッションが同じ案を再提案する
4. **司令塔が自分で書く**: サブエージェントに委譲しない。引き継ぐ内容はメインの会話コンテキストにしかなく、サブエージェントには渡らない
5. **短く保つ**: 長い handoff は読み込んだ時点でコンテキストを食い、区切った意味が薄れる。次のセッションが動き出すのに要らない記述は削る

## 手順

### 1. 出力先を決める

```bash
git_common=$(git rev-parse --path-format=absolute --git-common-dir)
repo=$(basename "$(dirname "$git_common")")
branch=$(git symbolic-ref --short HEAD 2>/dev/null || git rev-parse --short HEAD)
slug=$(printf '%s' "$branch" | tr '/' '-')
dir="$HOME/.claude/handoffs/$repo/$slug"
mkdir -p "$dir"
echo "$dir/$(date +%Y-%m-%d-%H%M).md"
```

git リポジトリの外にいる場合は `$repo` を `_no-repo`、`$slug` を `_` にする。

`--git-common-dir` を使うのは worktree のためである。worktree 内で `--show-toplevel` を使うと worktree のディレクトリ名が返り、メインリポジトリ名にならない。

### 2. 未コミットの変更を確認する

```bash
git status --short
git stash list
```

未コミットの変更が残っている場合、handoff に **どのファイルが未コミットか** を明記する。次のセッションは `git log` からは未コミットの変更を知れない。

### 3. ドキュメントを書く

一時ファイルに書いてから移動するのではなく、Write ツールで手順1のパスに直接書く。

構成は次の6セクション。**該当する内容が無いセクションは見出しごと省略する**。

```markdown
# <作業の一行タイトル>

- リポジトリ: <repo>
- ブランチ: <branch>
- worktree: <パス>
- 作成: <YYYY-MM-DD HH:MM>

## ゴール

<何を達成しようとしているか。ユーザーの元の依頼を、解釈を交えずに残す。
依頼が途中で変わった場合は変わった後のものを書く>

## 確定した事実

<検証済みのことだけを書く。各項目に根拠を添える。
- 実際にコマンドを動かして分かった挙動は、コマンドと出力の要点
- 公式ドキュメントで裏取りした事実は URL
- リポジトリ内のコードから読み取った事実は file:line
推測は書かない。書くなら「未確認」と明示する>

## 決定と却下案

<選んだ方針と、却下した案とその理由。
ユーザーが選択した事項は「ユーザーの判断」と明記する。次のセッションが
再提案して蒸し返すのを防ぐ>

## 未完了の作業

<次の一手を具体的に書く。「テストを追加する」ではなく
「<file>:<line> の <関数名> に <条件> のケースを追加する」のレベル。
待ち状態のもの（レビュー待ち、CI 待ち、サブエージェントの結果待ち）もここに書く>

## 触ったファイル

<コミット済みと未コミットを区別して列挙する。
未コミットの変更は、その内容も一行で添える>

## 再開手順

<新しいセッションが最初に叩くべきコマンド。
cd 先、fetch/rebase の必要性、起動すべきプロセスなど>
```

### 4. パスを提示して終了

書き出したパスをユーザーに返す。**セッションの終了や `/clear` は自分では行えない**ので、ユーザーに新しいセッションを開始してもらう。

新しいセッションでは `session-init` hook が同じリポジトリ・ブランチの最新 handoff のパスを SessionStart に出す。本文は自動では読み込まれないので、再開時に Read で読む。

## 注意点

- **サブエージェントに委譲しない**。引き継ぐ内容はメインの会話にしかない
- 秘密情報を書かない。トークン、パスワード、`.env` の内容は handoff にも書かない
- 既存の handoff を上書きしない。ファイル名にタイムスタンプを含めるのはこのため。同じブランチで複数回区切った場合、履歴として並ぶ
- handoff は成果物テキストなので `~/.claude/rules/communication-style.md` の対象。ただし `doc-style-checker` には渡さない。引き継ぎメモにサブエージェント1回分のコストをかける価値はない
- ドキュメントを書いたあとに作業を続ける場合、その分の変更は handoff に反映されていない。続けるなら書き直す
